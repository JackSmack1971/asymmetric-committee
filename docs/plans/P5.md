## Architecture

`BacktestOrchestrator` (`orchestration/pipeline.py`) is the one engine for backtest and single-period live runs. Celery (`orchestration/tasks.py`) wraps its stage methods; it never re-implements stage logic. Execution (`execution/`, `risk/kill_switch.py`) and anchoring sit after `COMMITTED`, per the §13 state machine:
`PENDING → INGEST_OK → FEATURES_OK → AGENTS_OK → COMMITTED → ANCHORED → EXECUTED → SCORED` (+ `FAILED`, `PARTIAL`).
Backtest mode stops at `COMMITTED` (no anchor/execution; scoring is P6). Live mode runs the full chain. Only paper endpoints exist (CLAUDE.md).

## Steps (each: tests first, small conventional commits)

### Step 1 — Stop-word guardrail + alias coverage (universe/, config/)
- Done: `STOP_WORD_ALIASES`, tests.
- Remaining: wire `assert_alias_coverage` at run start (Step 3) using the R6 loader; populate `config/aliases.yaml` for the included universe (owner, needs real backfill: `alias_coverage_gaps` lists what is missing). Run start fails closed on gaps.

### Step 2 — DB sink (`orchestration/sink.py`, `store/write.py`, Alembic)
- Tables per §4.3/§16: `runs`, `agent_verdicts`, `committee_decisions`, `portfolio_snapshots`, `decision_commitments`, `dlq_records`, `kill_switch_events`, `commitment_anchors`. Verify which exist before adding a migration (no duplicates).
- One transaction per `as_of` step; rollback leaves nothing partial. Insert-only for commitments (existing trigger). `model_served` stored from `response.model` (inv. 7). Task keys `(run_id, stage, security_id)`; only `COMPLETED` short-circuits (inv. 8).
- Tests: atomicity (fault injected mid-flush → zero rows), idempotent replay, commitment row precedes any outcome access (inv. 5).

### Step 3 — Pipeline (`orchestration/pipeline.py`)
- Weekly `as_of` stepping; every read via `store/as_of.py` (`available_at <= as_of`, inv. 2-3). Partition build (anonymized, inv. 4), `run_agents`, `RunBudget` from `pipeline.yaml`, pooling → stacker → `size_committee_book` → `run_cio`, then sink. `BudgetExceededError` → DLQ + `PARTIAL`.
- The gate runs inside `FEATURES_OK` (§13); commit before scoring (inv. 5). LLMs never output weights (inv. 6).
- Tests: failed run followed by a new run queues all names (§17 gate); budget breach → PARTIAL; look-ahead fixture; anonymity assertion on rendered prompts.

### Step 4 — Alpaca gateway + kill switch (`execution/alpaca.py`, `risk/kill_switch.py`)
- Paper endpoint only; a test asserts any non-paper base URL raises. Cancel/replace per §9 (client timer at 15 min, wait for cancel confirmation, reference-price rule). Reconciliation against fetched positions/orders. Never call live APIs in tests: respx fixtures.
- Kill switch per R1/R2, applied identically to benchmark books (T-bills). Stale-feed trigger reads freshness SLAs from `pipeline.yaml`.
- Tests: halt on -3% day, on stale feed, on manual (flatten); halted day moves benchmarks to T-bills; cancel/replace state machine incl. partial fills.

### Step 5 — Celery + anchoring (`orchestration/tasks.py`, `evaluation/anchoring.py`)
- Tasks wrap pipeline stages; retries with backoff; `POST /runs/{id}/reset` clears only that run's keys. Beat: weekly `run_pipeline(as_of=Friday_close)`.
- Anchoring per R3: sha256 of the commitment payload → `commitment_anchors`, OTS proof (`ots` client, mocked in tests; real stamp is network-gated), git commit hash. Merkle log optional addition.
- Tests: anchor recompute matches; tampered payload fails verification; run reaches `ANCHORED` only after a proof row exists.

### Step 6 — CLI, e2e, gate (`main.py`, `tests/orchestration/test_p5_e2e.py`, Makefile)
- `python -m main run-backtest | run-live | inspect-run` (load `pipeline.yaml`, DB pool, orchestrator). Live requires paper credentials from `.env`.
- e2e over mocked OpenRouter and Alpaca (respx), recorded fixtures only.
- `make gate-P5`: `make lint`, pytest over contracts/config/features/agents/committee/risk/universe/orchestration/execution with `REQUIRE_SERVICES=1`, `schema_export --check`. Replace the stub.
