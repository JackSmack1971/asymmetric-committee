# P0 — Contracts + config

## 1. Scope

§17 P0 deliverable: `contracts/` and `config/`. The docker-compose skeleton already landed in P-boot.
Spec: §1.3 (contracts before code), §3.1 (agent output contract), §7 (committee), §8 (risk/CIO),
§10 (LLM layer, models.yaml, strict structured outputs), §11 (run state machine), §13 row 1
(enum contract tests), §4.3/§4.4 (table shapes, universe filters).

Out of scope: DB, network calls, agents, prompts.

### contracts/
- `enums.py`: `AgentName`, `Stance`, `RunMode`, `RunStatus`, `TaskStatus`, `DataSufficiency`,
  `BearSeverity`, `CioAction`, `Horizon` (IntEnum 21/63), `FeedName`, `Stage`, `OrderSide`.
- `models.py`: `EvidenceRef`, `AgentVerdict`, `RedTeamVerdict`, `GateDecision`,
  `CommitteeDecision`, `CioDecision`, `ProposedBook`, `OrderIntent`, `FillReport`, `RunRecord`,
  `DecisionCommitment`, `OutcomeRecord`, `AgentScore`, plus LLM-output sub-models (see §5).
- Every model: `ConfigDict(extra="forbid", frozen=True)`; probabilities in [0,1];
  weights in [0, `MAX_POSITION`] (0.08, §8.1).
- `schema_export.py`: strict JSON Schema for LLM-facing models → `contracts/schemas/*.json`;
  `python -m contracts.schema_export [--check]`.

### config/
- `models.yaml` (fast/strong/probe; slug, fallback_slugs, stated_training_cutoff,
  supports_structured_outputs; TODO placeholders), `risk.yaml` (§8.1 + §8.2 veto budget + §9 kill
  switch), `universe.yaml` (§4.4; sectors TODO), `pipeline.yaml` (K=15, weekly rebalance, budgets).
- `loader.py`: Pydantic models (`extra="forbid"`) that load and validate all four files;
  `load_config()` raises `ConfigError` on any problem. Requires `pyyaml` (+ `types-PyYAML`).

## 5. Spec issues

Resolved with the owner on 2026-09-25: issues 1–3 accepted as proposed; blueprint §3.1 and
§10.2 edited in the same commit as this plan.

1. **§3.1 `data_sufficiency: Literal[...]` vs CLAUDE.md invariant 1** ("Enums, never bare
   strings"). Proposal: `DataSufficiency` enum; JSON schema is identical (`enum` of the same
   three strings). Blueprint edit: replace the Literal with `DataSufficiency`.
2. **§3.1 `horizon_days: Literal[21, 63]`** vs requested `Horizon` enum. Proposal: `Horizon`
   IntEnum (same wire values). Blueprint edit likewise.
3. **§3.1 mixes LLM-authored and system-filled fields, while §10.2 sends the verdict schema as
   `response_format`.** If the strict schema is the full `AgentVerdict`, the LLM must emit
   `model_served` (violates invariant 7), `run_id`, `as_of`, `prompt_version`, `entity_token`.
   Proposal: `AgentVerdictLLM` (stance, p_outperform, horizon_days, key_evidence, risks,
   data_sufficiency) is what the schema/LLM produces; `AgentVerdict` (exactly §3.1) = those
   fields + system envelope, built by `agents/base.py`. Same split for `RedTeamVerdictLLM` and
   `CioDecisionLLM`. Blueprint edit: §10.2 `VERDICT_SCHEMA` = schema of the LLM-output part.
4. **Minor:** `key_evidence` `min_length=1` even when `data_sufficiency == insufficient`.
   Proposal: keep as spec'd (agent must cite what it *did* see).
5. **Minor:** `risks` items unbounded length. Proposal: cap each at 280 chars (strict mode drops
   `maxLength` anyway, so Pydantic enforces it post-parse).
