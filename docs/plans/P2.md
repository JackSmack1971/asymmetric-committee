# P2 — Features, calibrated gate, quant baseline, and risk

## 1. Scope

Implement the deterministic §5 feature set (`fs_v1`), the §6 walk-forward logistic quality gate
with a complete shadow log, the §3 quant baseline, §8.1 deterministic risk sizing, and the minimal
weekly §12.2 walk-forward path. The path ends in a persisted `ProposedBook`; it invokes no LLM and
does not execute orders.

## 2. Design

- `features/`: pure calculators accept only contract rows returned by `store.as_of`; an orchestration
  adapter performs those reads. Price features use trading observations, fundamentals use the latest
  as-filed facts with explicit XBRL concept aliases, and insider/news windows use availability-safe
  rows. Fundamental percentile fields are calculated only across included members of the current
  universe snapshot. Rows are canonicalized and stored as `feature_set_version = "fs_v1"`.
- `gate/`: deterministic, dependency-free logistic regression with standardized numeric inputs.
  Labels are absolute security-minus-sector 21-observation returns, with the top tercile calculated
  cross-sectionally by label start. A training example is eligible only when `label_end < as_of`.
  The top `K` scores pass (stable security-id tie break), while every candidate gets a persisted
  `GateDecision` for shadow evaluation.
- `agents/quant_baseline.py`: cross-sectional sector-relative value, 12–1 momentum, and quality
  z-scores form an equal-weight composite. A logistic transform maps it to `pooled_p`; output is a
  `CommitteeDecision` with deterministic baseline metadata and no LLM dependency.
- `risk/`: pure sizing accepts committee-compatible decisions plus volatility and sector inputs.
  It applies entry/min/max-position rules, dispersion and bear multipliers, sector caps, and a
  conservative diagonal portfolio-volatility scale from `risk.yaml`. Cash is residual.
- `evaluation/walkforward.py`: for each weekly timestamp, read the current universe/facts through
  `store.as_of`, build and persist features, fit/score and shadow-log the gate, create baseline
  decisions, size them through the shared risk engine, and persist a run-linked proposed book.
  Storage writes remain isolated in `store/`.

## 3. Contracts and storage

- Reuse `FeatureRow`, `GateDecision`, `CommitteeDecision`, and `ProposedBook` contracts; add only
  deterministic baseline enum/contract support required for CommitteeDecision compatibility.
- Extend storage with explicit proposed-book rows linked to `runs`; store the full gate decision
  envelope needed to reproduce a shadow score. Migration and SQLAlchemy metadata stay synchronized.
- Persistence is idempotent on natural run keys; generated run IDs are stable from `(as_of,
  configuration)` where the runner is asked to replay the same schedule.

## 4. Tests first / acceptance

| Requirement | Check |
|---|---|
| No label leakage | Every selected gate training label has `label_end < as_of` |
| Feature determinism | Repeated construction for the same contracts and `as_of` is identical |
| Current-snapshot normalization | Sector percentiles exclude non-members and other snapshots |
| Risk constraints | Hypothesis random inputs always satisfy max position, sector cap, minimum, gross, and vol target |
| Shadow logging | Passed and dropped candidates are persisted |
| End-to-end | Synthetic fixture walk-forward over 12 weekly dates persists exactly 12 books |

`make gate-P2` runs formatting/lint/type checks and the focused feature, gate, baseline, risk, and
walk-forward tests. The fixture test reports gate recall over all fully realized weekly outcomes.

## 5. Decisions and boundaries

- `sigma_20d` is annualized (`daily return std × sqrt(252)`), matching the annual 12% portfolio
  target. The existing `k = 0.02` and `dispersion_lambda = 0.5` configuration values are adopted for
  P2 and recorded in progress; changing them is a config-only methodology change.
- Portfolio volatility uses a diagonal covariance approximation because §8.1 specifies per-name
  volatility but no covariance estimator. This is conservative only with respect to uncorrelated
  names; a covariance model remains a later methodology decision.
- Missing or invalid inputs produce `None` feature values. Gate/baseline standardization imputes the
  current training/cross-sectional median, never future data.
- Out of scope: LLM agents, committee pooling, CIO review, execution, transaction costs, and outcome
  scoring beyond the gate fixture recall report.
