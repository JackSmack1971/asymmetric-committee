Branch: `phase/P3`. Gate: `make gate-P3`.

## 1. Scope

The §17 deliverable is "Partitioner, anonymizer, 6 agents, OpenRouter client". Concretely:

- **Partitioner** (`agents/partitioner.py`): builds each agent's isolated input partition from `store.as_of` reads and `features` rows, and applies the name masker (`AliasMasker`, already done) and rule set N.
- **Rule-set-N renderer** (new module `features/renderer.py`): the only path from data to prompt text.
- **Agents** (`agents/`): Value, Quality+Catalyst, Insider, Technical, Macro/Narrative, and the Bear-case red team. `quant_baseline` already exists (P2).
- **OpenRouter client** (`agents/llm/`): strict structured outputs, model fallback, cache, per-model Redis token bucket, backoff, dead-letter queue, budget cap, cost accounting.
- **`agents/base.py`**: the only place that turns `AgentVerdictLLM` into `AgentVerdict` (`from_llm`) and computes `valid` (§3.1).
- **Prompts** (`prompts/<agent>/v1.md`): versioned rubric files.

Out of scope: committee pooling, calibration, CIO, sizing (P4); Celery state machine and Alpaca (P5); probes and scoring (P6). No live paid API calls anywhere; all tests use recorded fixtures and `respx`.

## 3. Design decisions

- **Partition isolation is by construction.** Each agent has a `Partition` builder that accepts only the row types in its §3 "Sees" column. The Value builder has no parameter for price rows, so a leak is a type error, not a runtime check.
- **Entity tokens.** `entity_token` (`TICKER_07`) is assigned per run by stable rank of `security_id`, never derived from the ticker. The mapping is stored on the run for later de-anonymization.
- **Rule set N in one module.** `features/renderer.py` renders ratios, growth rates, z-scores and percentiles (two significant figures for levels, N3), `t−37d` day offsets (N4), `Q−1…Q−20` fiscal periods, and market-cap tier only (N5). Every renderer has a fixture test; anything not on the allowlist raises.
- **Evidence references.** The partitioner emits stable row IDs. The validator rejects any `EvidenceRef` not in the partition it built (catches memory leaks).
- **`valid` (§3.1).** Computed in `agents/base.py` from `AppConfig.models` only: `RunMode.BACKTEST` and the served model's effective cutoff later than the run window → `False`; otherwise `True`. Live/ablation always `True`.
- **Client.** `models: [PRIMARY, FALLBACK]` in `extra_body`, `provider.require_parameters=true`, `data_collection=deny`, `response_format` from `contracts/schemas/`. `temperature`/`reasoning` sent only when `models.yaml` says so. Cache key `sha256(agent, prompt_version, model, input_partition_hash)`.
- **Failure policy.** One repair attempt, then the call is discarded as `invalid` (never persisted as a verdict). `UsageUnavailableError` aborts remaining calls and marks the run `PARTIAL`. Budget exceeded → same.
- **Persistence.** Writes go through `store/write.py` into `agent_verdicts` (already in `_tables.py`). Agents do not import `store.write` directly (import-linter); the runner receives a sink callable.

## 4. Steps (small commits; tests first in each)

1. **Config gap (P0 debt).** `ServedModel` lacks `family`, `measured_effective_cutoff`, `accepts_temperature`, `reasoning_effort`, `fallback_slugs`, and `effective_cutoff()`. Add them with the rest of `models.yaml`; loader rejects any primary or fallback missing a field. Test: missing-field rejection, `max(stated, measured)`.
2. **Rule-set-N renderer** (`features/renderer.py`) + numeric-leak test harness. (§17 lists this under P2, but no renderer exists; see §6.)
3. **Partition builders** for the five LLM agents + red team; entity-token assignment; evidence-ID scheme; identity + numeric leak tests over all of them.
4. **`agents/base.py`**: `from_llm` wiring, `valid` computation, evidence validator, repair/discard policy.
5. **Client core**: request builder, response parsing, served-model capture, cost via `ServedModel.call_cost`, fallback handling (`respx` fixtures).
6. **Client resilience**: Redis token bucket (requests and tokens), backoff with jitter (≤ 3 retries), dead-letter queue, cache, per-run budget, `PARTIAL` signalling. 429-storm load test.
7. **Prompts** `prompts/<agent>/v1.md` with rubric, the three system-defined horizons, and "insufficient data" definition; `prompt_version` derived from the file.
8. **Agent runner**: fans out (security × agent), run-scoped idempotency keys, sink callable for persistence; fixture end-to-end run on the synthetic universe.
9. **Gate**: `make gate-P3`; update `PROGRESS.md`.

## 6. Spec issues and gaps (need a decision or a spec edit; none silently resolved)

1. **Model config fields are missing in code** (§10.1 requires `family`, `measured_effective_cutoff`, `accepts_temperature`, `reasoning_effort`, fallback structure). Fixed in step 1; not a spec change.
2. **Rule-set-N renderer was assigned to P2 (§17) but not built.** Plan builds it here; PROGRESS should note the P2 gap. No spec edit needed.
3. **"6 agents" (§17) vs §3.** Read as five LLM agents plus the red team. The red team needs the top candidates, which come from the committee (P4), so P3 builds it against an explicit candidate list. **Proposed spec edit:** state this in §17 P3.
4. **`is_analyst_rating` (§4.3, §5) is absent from the code** (no match in `contracts/`, `store/`, `features/` or `ingest/`). Add it to the contract and the ingest parser before the news partitions (Quality+Catalyst, Macro) can filter analyst items.
5. **Insider "size as % of holdings"** needs `post_holdings`, which the contract has but only for non-derivative rows and may be null. Define the fallback (omit the field vs `insufficient`) before step 3. **Proposed spec edit** in §3.
6. **Numeric anonymization inputs.** N3 says percentiles "within the universe snapshot or sector, rounded to two significant figures"; `features` produces percentiles but not the rounding. Rounding lives in the renderer.
7. **Named executives.** §12.1 item 2 masks named people in news, but the alias list has no person names (only securities and brands). Form 4 `filer` names are the obvious source. Decide: add `AliasKind.PERSON` fed from `insider_txns.filer` (recommended, needs a contract change) or rely on role-only rendering plus a news-text name scrub.
8. **Cache storage** (§10.2) is unspecified: Redis or a table. Plan assumes Redis with the run's config hash in the key, so cache hits are never cross-config. Confirm.
9. **`agent_verdicts.cost_source`** column: spec §4.3 lists it; confirmed absent from `store/`; add the column, contract field and an Alembic migration.

### Decision 2 conflicts with existing spec sections

CLAUDE.md requires stopping and proposing a spec edit rather than diverging silently. The proposal contradicts:

- **§7.4:** the red team "does not vote". Decision 2 pools it as agent 6 in the stacking sum, which also changes the weight-propagation test (§7.5) and `contracts/`.
- **§3 roster:** replaces Value, Quality+Catalyst, Technical and Macro with Fundamentals, News, Price Features and ALFRED-based Macro. §4.1 has no ALFRED ingestor in P1, so a Macro agent on vintage series cannot be built or tested in P3.
- **§7 / §8.2:** replaces the calibrated pool with Platt scaling and extremizing (γ > 1), and the CIO with a conformal veto. Both are P4 scope and contradict the veto-budget design.

P3 needs only one answer from this: **is the red team a pooled voter, and is the roster changing?** Until answered, P3 keeps §3 as written (five LLM agents plus a non-voting red team). The extremizing and conformal ideas can be evaluated as P4 ablations without touching P3.
