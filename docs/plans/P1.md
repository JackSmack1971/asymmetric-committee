# P1 — Data layer

## 1. Scope

§17 P1 deliverable: bitemporal schema, the `as_of()` read path, four ingestors, universe snapshots,
feed freshness, backfill CLI. Spec: §1.2 (point-in-time everything), §4 (all), §13 rows
"restated fundamentals leak" and "stale feed trades", §15 layout.

Out of scope: features (P2 fills the `features` table), agents, kill switch wiring (P5 consumes
`feed_staleness`).

## 2. Design

### store/
- `store/_tables.py` (internal): SQLAlchemy Core `MetaData` for every §4.3 table plus
  `feed_health`. Every fact table (`price_bars`, `fundamentals_asfiled`, `insider_txns`,
  `news_items`, `features`, `universe_snapshots`) has `event_time`, `available_at`, `ingested_at`,
  `source_version`, a unique natural-key + `source_version` constraint and an index on
  `(security_id, available_at)` (news: GIN on `security_ids[]` + btree on `available_at`).
- `store/migrations/` (Alembic, `alembic -c store/alembic.ini upgrade head`; `store.migrate`
  runs it from code). Migration 0001 is explicit `op.*` DDL; a test runs Alembic's
  `compare_metadata` against `_tables.metadata` so they cannot drift.
- Hypertables: `price_bars` and `features` on `event_time`. The migration requires the
  `timescaledb` extension unless `STORE_ALLOW_PLAIN_POSTGRES=1` (local test clusters without the
  extension). CI runs the `timescale/timescaledb:latest-pg16` service, so hypertables are tested there.
- Immutability: triggers reject `UPDATE`/`DELETE` on `fundamentals_asfiled` (as-filed, never
  overwritten) and `decision_commitments` (append-only).
- **Version rule** (one rule for every fact table): per natural key, among rows with
  `available_at <= as_of`, the winner is the max `(available_at, source_version)`. A restatement is a
  new accession with a later `available_at`; a news revision is a new row; a SIP bar supersedes the
  live IEX bar once its `available_at` passes.
- `store/as_of.py` — the only read path: `prices`, `fundamentals`, `insider_txns`, `news`,
  `features`, `universe`, `securities`, `feed_staleness`. Each takes a `Connection` and an aware
  `as_of` and returns frozen contract models. Built on one private `_latest()` (`DISTINCT ON` key,
  ordered by `available_at DESC, source_version DESC`).
- `store/write.py` — ingest-side writes; every write is `INSERT … ON CONFLICT DO NOTHING` on
  natural key + `source_version`, so re-running an ingestor is a no-op.
- Row shapes are contracts: `contracts/data.py` (`PriceBar`, `FundamentalFact`, `InsiderTxn`,
  `NewsItem`, `FeatureRow`, `Security`, `UniverseMember`, `FeedHealth`, `FeedStaleness`) with new
  enums `PriceFeed`, `InsiderRole`, `InsiderTxnCode`, `NewsProviderName`, `McapTier`.
- Enforcement (invariant 2): import-linter `forbidden` contract — `agents`, `features`, `gate`,
  `committee`, `risk`, `evaluation`, `universe` may not import `sqlalchemy`, `psycopg`,
  `store._tables`, `store.write`, `store.migrate`; ruff `TID251` bans `store._tables` outside
  `store/`. `make lint` runs `lint-imports`; a test asserts the contract exists and passes.

### ingest/
- `ingest/http.py`: shared httpx plumbing + `ReplayTransport` / `RecordingTransport` keyed on
  `host/path?sorted-query`. Tests and the gate replay files from `tests/fixtures/http/`; recording
  real responses is `python -m ingest.backfill --record tests/fixtures/http …` (network needed).
- `ingest/edgar_client.py`: `SlidingWindowLimiter` — a Redis ZSET + Lua sliding-window log (atomic,
  Redis clock, shared across all workers), default 8 per 1.05 s window (5% margin for request
  jitter). `EdgarClient` (sync httpx): User-Agent from `SEC_USER_AGENT` (required), limiter before
  every request, exponential backoff honouring `Retry-After` on 403/429.
- `ingest/alpaca.py`: daily bars. History (`end <= now - 15m`) uses `feed=sip`,
  `available_at = session close (16:00 ET) + 15m`; live uses `feed=iex`, `available_at = receipt`.
  `source_version = feed`. Market-data host only; no trading endpoint is touched.
- `ingest/edgar_xbrl.py`: companyfacts (`us-gaap`, `dei`) → one row per
  `(concept, unit, period_start, period_end, accession)`. `available_at` = acceptanceDateTime from
  the submissions index (recent + older pages); if an accession is missing, fall back to the end of
  the `filed` date in ET (never earlier than true acceptance). Insert-only.
- `ingest/edgar_form4.py`: submissions → Form 4 / 4/A → XML (non-derivative table): code,
  shares, price, A/D, post-transaction holdings, role, 10b5-1 (`aff10b5One` checkbox, else footnote
  text). `event_time` = transaction date, `available_at` = acceptanceDateTime.
- `ingest/news.py`: `NewsProvider` protocol; `AlpacaNews`, `AlphaVantageNews`; chosen by
  `NEWS_PROVIDER`. `revision` = provider update stamp + body hash, so an edit is a new row.
  Backfill `available_at` = the provider's last-update time (we only hold the latest text), live =
  receipt time. `timestamp_audit()` flags items whose stamps look unreliable.
- `ingest/freshness.py`: `record_feed_run` → `feed_health`. SLAs live in `pipeline.yaml`
  (`freshness_sla_hours`); `store.as_of.feed_staleness` reports stale feeds.
- `ingest/backfill.py`: `python -m ingest.backfill --years 2 --universe config/universe.yaml
  [--tickers …] [--end DATE] [--replay DIR | --record DIR]`.

### universe/
- `universe/sectors.py`: SIC → sector map (securities carry the SEC SIC-derived sector).
- `universe/snapshot.py`: month-end snapshots via `as_of` reads only: listed on the date, sector in
  set, market cap (dei shares outstanding × close) in band, ADV20 ≥ min, price ≥ min; rank by
  `log(ADV20)` (SPEC-GAP: "liquidity-adjusted score" is undefined) and include the top N. Every
  evaluated candidate is stored with `included`, so past snapshots keep delisted names.

## 5. Gate
```
gate-P1: lint            # ruff + mypy --strict + import-linter
	REQUIRE_SERVICES=1 uv run pytest tests/store tests/ingest tests/universe tests/config
```
The backfill smoke (5 tickers x 90 days, `--replay tests/fixtures/http`) runs inside
`tests/ingest/test_backfill_smoke.py` via `ingest.backfill.main`, and again to prove idempotency;
`make backfill-smoke` runs the same CLI against `$DATABASE_URL`. Tests find Postgres via
`TEST_DATABASE_URL` or start a throwaway `initdb` cluster; Redis via `TEST_REDIS_URL` or a throwaway
`redis-server`. With `REQUIRE_SERVICES=1` a missing service fails instead of skipping. CI runs the
TimescaleDB and Redis images with `REQUIRE_TIMESCALE=1`, so hypertables are checked there. The
"2 years backfilled" part of §17 needs network and keys; run `--years 2` once credentials exist.

## 6. Spec issues / decisions
1. §4.3 additions (edited in this commit): `fundamentals_asfiled` gains `period_start`,
   `fiscal_period`, `form` (Q and YTD facts share `period_end` and accession); `news_items` gains
   `summary`; `price_bars.ts` is named `event_time`; new `feed_health` table.
2. Fixtures are **synthetic** (this environment has no route to SEC/Alpaca/Alpha Vantage). They
   follow the documented response shapes and are replayed through the same transport a real
   recording would use. Re-record with real responses before trusting parsers in production.
3. Alpha Vantage `time_published` has no zone; treated as America/New_York (the later reading, so
   never look-ahead). Alpaca news gives no revision history; backfilled items are only visible from
   `updated_at`. Both need a check on real recordings before §18.1 is decided.
4. EDGAR `acceptanceDateTime` carries a `Z` but its digits are Eastern wall time (they match the
   filing header). Read as Eastern, the later reading, so never look-ahead.
5. Seeding from SEC `company_tickers_exchange.json` lists only current names, so pre-P1 delistings
   are missing (survivorship). Snapshots are survivorship-safe from P1 on.
