# P6.4 Corporate actions + delistings

Branch `phase/P6` (local, fast-forwarded to `main` 98cd047 on 2026-09-27; not pushed). Spec: blueprint §4.3, §4.6 (edited with the owner decisions below). P6.4 stores evidence only: no outcomes, returns, benchmarks or metrics (P6.5+).

## Owner decisions (2026-09-27)

1. `available_at` = first observation of each provider version; never backdated. `backfill` rows are sensitivity/debug only; readers exclude them unless `include_backfill=True`. Periods without contemporaneous evidence stay UNRESOLVED.
2. `security_symbols` keeps one `security_id` across an explicit name change. Never ticker-as-identity, never merge on CIK alone (multi-class issuers).
3. Delisting hierarchy (first match wins): terminal action with consideration → CONSIDERATION; worthless removal → −100%; terminal action without consideration → −30% DEFAULT; name change → IDENTITY_CHANGED; status-derived DEFAULT needs ≥ 2 inactive polls ≥ 1 confirmed session apart + effective Form 25 + complete action coverage with no terminal/identity action + confirmed calendar; ≥ 10 confirmed missing sessions while active → SUSPECTED_GAP only. Form 15 not required. Later consideration supersedes DEFAULT as a new row.
4. Spin-offs, rights, reorganizations, unit splits, partial calls: stored, `uninterpreted`; a window containing one is UNRESOLVED.

## Provider semantics (pinned from the Alpaca API reference, 2026-09-27)

`GET https://data.alpaca.markets/v1/corporate-actions`: `start`/`end` inclusive on **`process_date`**; `types` (15 listed); `data_quality` default `complete`; `region` default `us`; `limit` ≤ 1000 with `next_page_token` (required key, null at end). No creation-time guarantee. Coverage rows therefore describe process-date ranges, clamped to the day before the fetch.

## Known limits

- Fixtures are synthetic (shaped like the API reference examples); record real responses before trusting production parsing. Whether `symbols=` matches `old_symbol`/`acquiree_symbol`/`source_symbol` is unverified.
- Form 25 attribution requires an issuer with exactly one security; multi-class issuers never reach the status-derived default.
- A pre-existing duplicate identity (the new ticker already seeded as another security) is recorded in `identity_conflicts` and reported; it is never merged automatically (see P6.4a).

## P6.4a closure fixes (2026-09-27)

A read-only closure audit found four defects and two hardening gaps; all fixed, still uncommitted.

- **D1 dated attribution.** `SymbolResolver` (contracts) resolves an action's subject symbol on its `process_date` (name change: the day before) from all securities' `security_symbols`. Held outside the batch → not ours; unknown/ambiguous → coverage withheld for the batch securities that ever used the symbol (reported). New `corporate_actions.subject_symbol`.
- **D2 rename conflicts.** Actions + coverage commit first; name changes apply in their own transaction. A target ticker held by another security → `identity_conflicts` row, no mutation, job error for the owner. `ensure_security` no longer maps a retired symbol to its former holder; a reusing security's seed starts on its creation date.
- **D3 consideration.** Known stock terms (acquirer symbol + ratio) stay `consideration`; `delistings.acquirer_symbol` stored; acquirer resolved at derivation from dated symbol history; unresolved → NULL, never default.
- **D4 Form 25.** `earliest_effective_date` (filing + 10, a floor) and nullable `stated_effective_date` (not yet parsed from documents); amendments (`25/A`, `25-NSE/A`) stored; superseded by P6.4b (path-specific dates; amendments restart the clock).
- **H1.** Withdrawal needs the prior `subject_symbol` in the new coverage's `symbols`.
- **H2.** Primary readers are prospective-only (no switch); `store/as_of_sensitivity.py` holds the backfill readers, forbidden by import-linter to agents/features/gate/committee/risk/evaluation/universe/execution/orchestration. Backfilled name changes never move identity.

## P6.4b Form 25 timing (2026-09-27)

A final read-only check against 17 CFR 240.12d2-2 and the SEC Form 25 General Instructions found that D4 applied the (b)/(c) 10-day rule to paragraph (a) and treated amendments as blocking forever. Corrected (uncommitted):

- `Form25Provision` (`a1`–`a4`, `b`, `c`) and nullable `delisting_filings.rule_provision`. Issuer `25`/`25/A` → `c` (validated); exchange `25-NSE`/`25-NSE/A` → None until its document is parsed; `c` on an exchange filing is rejected.
- `_effective_form25`: one base filing plus amendments (several bases fail closed); the latest filing anchors the floor (amendment restarts the clock); `b`/`c` → floor; `a1`–`a4` → stated date ≥ floor required; unknown paragraph → fail closed. The later inactive poll must be on/after the derived date; coverage and calendar requirements unchanged; Form 15 still rejected.
- Commission postponement ((d)(3)) is not observable on EDGAR: documented residual risk, never claimed absent.
- Operational blocker: exchange `25-NSE` documents are not parsed (no recorded filing exists), so exchange-filed delistings cannot reach the status-derived default until a parser for the paragraph checkbox and specified date is built from real recordings.
